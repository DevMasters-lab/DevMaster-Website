All exact fields, lengths, defaults, enums and support tables are proposed v1 specifications. The source fixes the business model, not a deployed schema. |  |  |  |  |  |  | 
PK = primary key; FK = foreign key; UQ = single-column unique constraint. Multiple PK-marked identifiers in a bridge form one composite primary key. |  |  |  |  |  |  | 
Nullable = database-level nullability. Required-on-issue rules still apply to draft offer fields. “None” means no default; it does not mean an optional field. |  |  |  |  |  |  | 
All timestamps are proposed as timestamptz(3); dates remain date. UUID identity and integer record_version are proposals. Apply updated_at and record_version changes in every write path. |  |  |  |  |  |  | 
Default FK actions: RESTRICT on delete/update. Preserve history by disabling or archiving records. Retention durations, legal policy wording and controlled purging remain unresolved. |  |  |  |  |  |  | 
IMPORTANT: accepted offer ≠ selected expert. Selection must reference the exact valid acceptance. Issued terms and file-version references are preserved. |  |  |  |  |  |  | 
This package is documentation, not an executed migration. Planned tests have not been run against an application or database. |  |  |  |  |  |  |
